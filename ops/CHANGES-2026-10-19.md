# NewsAgg changes — 19 October 2026

All work is on branch `local-postgres` (not yet merged into `main`).
Every commit is authored by Riyaka許家豪.

## 1. Database moved from Neon to local PostgreSQL — `f7222e3`

- Neon's free plan ran out of its 100 monthly compute hours, so the live database now runs in Docker Compose as the `db` service: PostgreSQL 18.6 with pgvector, data in the `pgdata` volume.
- The final Neon dump (21:44) was restored locally. Row counts matched in all 20 tables, including users, sessions, posts, comments, likes and bookmarks.
- Connections:
  - Containers reach the database as `db`.
  - Host-side scheduled scripts use `127.0.0.1:5433`.
  - The old Neon address is kept as `NEON_URL_BACKUP` and is no longer read.
- Four helper scripts that always demanded TLS now skip it for local hosts.

## 2. Admin account and tools — `a022b18`

- `newsaggtest123@gmail.com` (NewsAggTest) is the only account with `role = 'admin'`.
- **Admin page** (`/admin`, sidebar shows a badge with open reports):
  - Overview: users, posts, articles, open reports and database size by table.
  - Reports: article reports (resolve, reject, reopen) and post reports (hide post and resolve, dismiss, reopen).
  - Users: list with permanent deletion. Admins and the signed-in admin cannot be deleted.
- Admins can delete or restore any post from the feed.
- Every new article or post report emails the admin. Report text is escaped in the email.
- **Database viewer** at `/dbviewer/`:
  - Nginx asks the API whether the session is an admin's before letting a request through.
  - The viewer is read-only, uses a locked session and logs in as `newsagg_viewer`.
  - `newsagg_viewer` cannot read password hashes, Google ids, login tokens or sessions. Account rows appear in the `users_overview` view.

## 3. Accounts, profile, article panels and SEO — `f606934`, `ff4daf5`

- **Password change:**
  - The current password is always required.
  - The new password must differ from the current one and be typed twice (Confirm new password).
- **Google-only accounts** cannot set a first password from a session alone. They request a single-use link by email (`POST /api/account/password-link`), which proves the inbox is theirs.
- **Profile page:**
  - The email address and last-active time are masked behind an eye toggle.
  - The Danger zone uses a warning sign.
  - The settings grid no longer overflows on phones.
- **Article page:** all side panels share one heading icon style (`PanelHeading`).
- **SEO:** Cloudflare Quick Tunnels add `X-Robots-Tag: none` to every response, which blocked indexing.
  - The Worker now removes that header for reader pages.
  - It sends `noindex, nofollow` for `/api`, `/auth`, `/admin` and `/dbviewer`.
  - Lighthouse SEO went from 66 to 92.
  - The remaining SEO point is Cloudflare's own "managed robots.txt" text (Cloudflare dashboard setting).
- **Performance:** unused preconnects became `dns-prefetch`. The score is limited by the Quick Tunnel round trip (about 1 s per request; the API itself answers in about 5 ms). Edge caching was tested, but it does not work on `workers.dev`, so it was not kept.

## 4. Weekly backup and cleansing — `b08b653`, `0ae79e3`

- The daily backup was replaced by the Windows task **NewsAgg Weekly Maintenance**, which runs every Sunday at 21:30:
  1. It waits if an ingestion is still running.
  2. It takes a `pg_dump` backup into `backups/`, keeping the newest 8.
  3. It runs `scraper/cleanup.py --commit --vacuum`.
  4. It writes its log to `logs/db-maintenance.log`.
- **Cleansing deletes:**
  - articles published more than 45 days ago;
  - articles the website can never show, once they are older than 7 days: failed the publication gate, extracted before `structured-v3`, without reader blocks, without a photo, or quarantined;
  - rejected staging candidates older than 14 days, and published ones whose article is gone;
  - orphan translations and authors;
  - publication receipts of deleted articles.
- **Never deleted:**
  - protected, bookmarked or posted articles;
  - the 120 frozen NLP evaluation articles (`scraper/protected-evaluation-ids.txt`);
  - accounts, posts, comments, reports and newsletter history.
- **First run (19 Oct, 23:15):**
  - A backup was taken first: `backups/newsagg-20261019-2315.dump`.
  - Then 5,951 articles, 116 receipts, 3,835 staging rows and 15,513 orphan authors were deleted.
  - The database now holds 3,158 articles, and the website shows 3,105 of them. The rest are 10 hidden duplicates, 41 recent unshowable stories (removed next week) and 2 protected articles.

## 5. Public window and photo rule — `0ae79e3`

- The public feed now covers **45 days**, the same span the cleanup keeps (previously 30 days).
- Stories without a publisher photo are no longer published:
  - The scraper rejects them as `no_image` before running the NLP models.
  - The publication gate no longer accepts the "image unavailable" fallback.
- The 142 stored stories without a photo (140 Yahoo TW, 1 BBC, 1 CNN) were marked `feed_eligible = false`.
- The scraper image was rebuilt for the next 17:00 ingestion. The previous image is tagged `website-scraper:before-no-image-20261019`.
- The Methodology, Research and Legal pages now describe the 45-day window, the photo rule, the weekly cleanup and the 05:40 / 05:50 schedule.
